# Conventions

How the code is put together and the rules for changing it. Read before changing `sim/`, `view/` or `test/`. Each public method's meaning is in its doc comment; this file holds what the code does not say.

## Layout

- `sim/`: the simulation. Every class is `RefCounted` with a `class_name`; nothing here touches the scene tree, `Input` or rendering. `DiveSimulation` is the one seam; `Medium`, `MediumLayout`, `SurveyStretch`, `ColumnFeature` and `ScanPoint` are data it reads or hands out. `Heat`, `Plasma` and `Stranding` are subsystems it owns (see Subsystems). `Scenario` is the data of a Scenario and `Checklist` the dive's progress through it (see Scenarios).
- `view/`: scenes and view logic. `view/habitat.tscn` is the main scene. `Arm` (`view/arm.gd`), `HullGroans` (`view/hull_groans.gd`), `KeyMap` (`view/key_map.gd`) `ChecklistPanel` (`view/checklist_panel.gd`; `ChecklistPanel.text_of()` is the Tab panel's text, tested directly) and `KeyPrompt` (`view/key_prompt.gd`; `KeyPrompt.rect()` builds a screen-space prompt for the F1 controls and the debug menu) are view logic as plain `RefCounted`s, tested directly (plain transforms; a seeded RNG; plain data).
- `assets/`: vendored assets, each folder with a note of its source and licence. `assets/prompts/keyboard/` holds the key prompt images (Xelu's CC0 pack, the light keyboard set).
- `test/`: GdUnit4 suites, `*_test.gd`, `extends GdUnitTestSuite`, `func test_...`. Shared helpers in `test/support/dive_test_kit.gd`.
- Commit the `*.gd.uid` files Godot generates beside each script.
- Files are LF. On Windows, write files from Python with `newline=''`, or they come back CRLF.

## Running

Tests: set `GODOT_BIN` to a Godot 4.7 binary (on Windows the `_console.exe` build), then `./test.sh` or `test.cmd`. Exit 0 is a pass, 100 a test failure, 105 a script or parse error.

- The wrappers run an `--import` pass first. Without it a fresh checkout fails discovery with "Could not find type" for `class_name` classes.
- Every run prints `ERROR: Remote Debugger: Unable to connect to host '127.0.0.1:0'`. That is GdUnit4 disabling the debugger on purpose.
- A low test count means a failure: GdUnit stops a suite at its first failing test.

Scene smoke check: `"$GODOT_BIN" --headless --path . --quit-after 120`. Success prints only `WARNING: 1 ObjectDB instance was leaked at exit` (a playing `AudioStreamGenerator`'s playback, engine behaviour). Any script error is a real failure.

Ad-hoc checks: a `SceneTree` script outside the repo, run with `-s <script>`, can load `res://` scenes. Such runs go in real time (60 physics frames per simulated second). A non-headless one can save `get_viewport().get_texture().get_image()` to PNG for a visual check. To look into the Bore, add your own `Camera3D` and call `make_current()` a frame after adding it (the crew's camera claims current in its `_ready`); (2.6, 0, 0) looking at the origin sees between two Stations. Hide `Overlay` for a clean shot. Prefer headless checks when a window isn't needed.

## The simulation's interface

`DiveSimulation.new(layout)`, then: commands in, `advance(dt)`, state and events out. The shape is in the class's header comment; copy it.

- **Commands** are one method per Station command (`set_power()`, `set_course()`, `shift()`, `pulse()` ...). They clamp, and take effect on the next step. A Station's command that needs the crew present checks `attended()` (as `override_course()` does); one that self-destruct takes off the crew starts with the one guard `if _off_the_crew(): return`.
- **State** is read-only query methods; no public vars. Values like `speed()` and `slip()` are recomputed each step, so read them after `advance`.
- **Events**: `take_events() -> Array[Dictionary]`, each `{type = &"...", ...fields}`. Raise one by appending to `_events`, and list it in `take_events()`'s doc comment, which is the catalogue. In the view, `habitat.gd` is the one consumer (each frame after `advance`); anything else that wants events gets them from the Habitat.
- **Time**: `advance(dt)` runs `dt * time_rate()` seconds, split into steps; per-step work lives in `_step(dt)`. A Station call returns the rate to 1 and drops the rest of that advance. `advance` does nothing while `surfaced()` or `dead()`. While `stranded()` it runs `_step_stranded(dt)` instead: nothing moves and the Head is dark, but a relight is tried, heat soaks into the hull (`Heat.soak()`) while Thermal's pumps cool it on the store, the link sends on the store, the hull may fail, and the rescue may arrive; anything else that runs with the Head dark goes there. Stranded, the time rate may be raised even though the Reactor calls.
- **Tuned constants** are private `const _NAME` with a comment citing ADR 0001. Tests never reference them; a test that needs a size reads it through a query (`stretch.length`, `minimum_turn_radius()`, `vessel_length()`).
- **Per-step cost**: per-step code must not scan the whole survey; a long dive has thousands of stretches.
- **No extraction**: a test fails any `DiveSimulation` method whose name contains extract, sample, cut, collect or remove (substrings, so `execute` fails too). The Bore Station observes and records; nothing leaves the Column.

### Frames and units

- Habitat frame = the Habitat node's axes: `TOWARD_HEAD` is -Z (Head end cap at z = -1.2), `TOWARD_UNDERSIDE` is -Y. `felt_acceleration()` is in this frame.
- World frame: origin at dive start, +Y up, so `depth() == -head_position().y`. Heading 0 is along -Z, 90 along +X. Pitch +90 is the Head straight down, -90 straight up.
- Path distance (`distance()`, metres along the path since the dive began) is what survey stretches, features and the Column are positioned in, not depth. The path is 3D; map a path distance to the world with `_depth_at_distance()` / `_medium_at_distance()`, which read the remembered path (`_remember_path()`).
- Power is one budget in the units of `set_power()`.

## Extension points

**A new power-drawing system.** Add its request in `_share_power()`, slotted into the shortfall order (Navigation, then Thermal, then the Drive: each gets all it asks while power lasts), and add its draw to `power_drawn()`. Heat follows, since `Heat.step()` makes heat from `power_drawn()`. Starvation is `<station>_supplied() < 1`; decide what a starved system does.

**Reactor output.** `reactor_output()` scales with `Plasma.stability()`; anything that unsteadies the plasma lowers that (in `Plasma.tend()`), and it flows through the budget with no other change.

**Survey quality.** `_recording_quality()` is the one hook: today the shutter term (Quiet Ship) times `Heat.unheated_share()` (heat into the Column). A new effect multiplies in another term there. Survey stretches and feature recording both read it, so nothing else changes.

**New dives.** `new_dive()` (after surfacing, being brought home through the tunnel or a rescue, or after death: the rebuy) calls `_start_fresh()`, which resets every script variable to a fresh simulation's except `_KEPT_BETWEEN_DIVES`. There is no `recover()`: a stranding ends in a relight, the rescue (automatic, `rescue_time()` after the stranding) or death. A new per-dive variable needs nothing. A variable that must survive (what was paid, where the crew is) goes in that list; a test in `stranding_test.gd` checks the list against the script's variables. The subsystems (`_heat`, `_plasma`, `_stranding`) are replaced whole by a fresh simulation's, so a new variable inside one starts over with no work; one that must survive into the next dive lives on `DiveSimulation`, not in the subsystem. Station settings return to their start, so the view re-sends its own (`habitat.gd::_reset_settings`).

**A new Station call.** Add an `_offer_call(calls, station, reason, urgency)` in `_update_calls()`, with urgency from `_urgency(_<KIND>_CALL, share)` and a new `const _<KIND>_CALL := Vector2(begins, worst)` beside the others, never an inline number. A call that begins or changes reason raises `&"station_call"` and drops the time rate to 1.

**Autopilots.** Each Station's autopilot is a switch, A320 style: `set_autopilot(station, engaged)` (E at every Station), read with `autopilot(station)`. The switch alone decides whether a Station steadies itself; attendance (`set_attended()`) matters only for commands that need the crew there (the Drive's override, self-destruct's hold), so a crew member can stand and watch an autopilot work. Every autopilot starts off each dive (`_autopilot` is per dive). Any Station command other than a reading (one that changes a setting, or acts as `shift()` and `relight()` do: the crew taking the controls) starts with `_disengage_on_command(STATION_...)` after its guards, which disengages its autopilot and raises `&"autopilot_off"` with `cause` `AUTOPILOT_OFF_BY_COMMAND` (the switch's own cause is `AUTOPILOT_OFF_BY_SWITCH`); a reading (`pulse()`, `set_observed_feature()`) does not call it. A new command calls it unless it only takes a reading. Off, a Station holds its setting and does nothing more; its calls still come. Engaged, its steadying rule runs in `_steady_autopilots()` (Drive backs power off to the grip limit while slipping; Thermal raises the heat split while the hull warns), or in its own place: the Reactor's late Shift in `Plasma.tend()` (passed `autopilot(STATION_REACTOR) or _self_destructing`), the Drive's gentle steering cap in `_steer()`. Engaging the Drive's sets its slow, safe power (`_AUTOPILOT_DRIVE_POWER`) and ends any override, so a plotted Course plus the Drive's autopilot gets the vessel moving. A new Station's rule goes in `_steady_autopilots()` behind `autopilot(STATION_...)`. A test that wants a Station to steady itself engages its autopilot (see Testing).

**Self-destruct.** Held commands are counted in the simulation, not the view: the view reports whether the key is held each frame (`hold_self_destruct(held)`) and `advance()` counts the hold in real seconds (its `dt`, before the time rate) at an attended Station, so the hold is testable at the seam. While `self_destructing()` the Stations are off the crew: Station commands return early on `_off_the_crew()` (the Bore Station's stay the crew's, so the link can still send), the Reactor's Shifts go to its autopilot whatever its switch, `_steady_autopilots()` does nothing, the autopilots' switches (but the Bore Station's) are ignored and calls do not hold down the time rate. Under way `_mismanage()` sets the settings each step; stranded it is one more store consumer, `_dump_draw()`, drawn first and counted in `stranding_clock()` (passed to `Heat.soak()` / `time_to_fail()` as `dumped` power). `&"hull_failed"` carries `cause` (`&"heat"` or `&"self_destruct"`), and `cause_of_death()` keeps it after death, so every screen names the same cause. It is not a one-way door: `_start_self_destruct()` keeps the crew's settings (`_crew_settings`: power, heat split, Quiet Ship) and `cancel_self_destruct()` puts them back; only the wear and the store spent stay. A plasma lost meanwhile strands it into the dump, and `_strand()` zeroes the kept heat split too, since the pumps stopped with the Head. A setting self-destruct comes to touch goes in `_crew_settings`. A hold that could do nothing (stranded with the store empty) does not count: `can_self_destruct()`.

**The emergency store.** One store of energy (`Stranding`, read as `emergency_store()`) for everything that runs once the plasma is lost (`on_emergency_store()`). A consumer that can run on less (the link, cooling) takes `_stranding.draw(energy)` each step and scales its effect by what it got (cooling draws first, then the link); what each draws a second is reckoned once (`_cooling_draw()`, `_link_draw()`), for both `_step_stranded()` and `stranding_clock()`, so the clock and the death it predicts cannot drift; a new consumer gets its own such method and is added to both; one that needs all at once (a relight's pulse) calls `_stranding.pay(energy)` and is refused on false. It is full at the start of every dive and is not drawn while the plasma holds. Energy is in the units of `set_power()` times seconds.

**Payment.** A stretch pays `SurveyStretch.value()` once all of it is up the link. Death's breakdown is the `&"hull_failed"` event: `rebuy` is the cost, `rebuy_charged` what was taken (0 until a balance exists; charging it is a later ticket). Surfacing, being brought home through the open tunnel and a rescue all end in `_come_home(arrival, rescue_seconds)`: it raises the arrival event (`&"surfaced"`, `&"brought_home"` or `&"rescued"`), sells what is aboard through `_sell_aboard()`, bills the dive's wear through `_pay_for_repairs(rescue_seconds)` (a `Repairs`, whose `total()` is the one sum of the bill), then raises `&"paid"`, which carries the arrival event as `arrival` so the view heads the breakdown from it alone. The bill is the hull's (`Stranding.hull_repair(vessel_wear())`) and the Head's (`Stranding.head_repair(head_wear())`), each in proportion to wear, never running hours, and a rescue's in proportion to how long it took (`Stranding.rescue_cost()`). `&"paid"` carries `hull_repair`, `head_repair` and `rescue`, and `amount` is net of them, but never below 0: `_pay_for_repairs()` charges no more than the dive earned (`_paid - _paid_before_dive`), and the rest of the bill is `Repairs.covered`, carried as `covered` and shown as its own breakdown line ("on us"), so `amount = by_link + carried_home - repairs + covered`; `by_link` (counted as the link pays, `_paid_by_link`, never a difference) `+ carried_home` (and the `by_medium` total) is the pay before repairs. A new cost of a dive that reaches the surface goes in `Repairs` and `_pay_for_repairs()` and becomes another field and breakdown line. A fully recorded feature becomes a `SurveyStretch.feature_record()` on the link queue, not an entry in `survey()`. For "aboard" counts use `unsold_survey()` / `unsold_value()`, not `survey().size()` minus uploads: `uploaded_survey()` spans every dive. Heat and shuttering's cost is `pristine_value() - value()`.

**Debug commands.** The developer's shortcuts for testing a dive by hand live on `DiveSimulation`, in their own section ("Debug commands", after the Station commands), each named `debug_*` and returning a `StringName`, `&""` when it acted or why it could not (the catalogue is the section's header comment; the debug menu shows it, `DebugPanel.REFUSALS`): `debug_wear_hull(amount)`, `debug_hull_to_brink()`, `debug_wear_head(amount)`, `debug_lose_plasma()`, `debug_strand()`, `debug_refill_store()`, `debug_surface()`, `debug_skip(seconds)`, `debug_self_destruct()`, `debug_shift_due()`, `debug_next_boundary()`. They are not crew controls: no Station works them, they ignore attendance and self-destruct's lock on the Stations, and each reaches the state it names at once (not on the next step), going through the simulation's own paths (`_check_stranded()`, `_surface()`, `_rescue()`, `_start_self_destruct()`, `_step()`, `_follow_the_head()`) so its events and consequences are the real ones: surface now while stranded is the rescue arriving, billed. Every one starts with the one guard `if _debug_dive_over(): return &"dive_over"`. A subsystem's state they set goes through its own `debug_*` method (`Heat.debug_set_wear()`, `Plasma.debug_set_wear()` / `debug_lose()` (through the plasma's own `_lose()`, which raises `&"plasma_lost"`) / `debug_mistune()`, `Stranding.debug_refill()`), never a crew command. Their sizes are `_DEBUG_*` constants, debug settings, not tuned for play. Each is tested in `debug_command_test.gd` to reach the state it names. A new one: a `debug_*` method here with a test, then a key in the debug menu (see Key map). Crew-facing code and tests of the game never call them.

**Scenarios.** A Scenario (`sim/scenario.gd`, `Scenario`) is plain data: a title, a layout, a start state (`prepare`, a Callable given the simulation at the start of each of its dives), the Orders (`Scenario.Goal`), the Checklist (`Scenario.Phase`s of `Scenario.Step`s) and surface control's messages (`Scenario.Message`). Every condition is a `Callable(sim, events) -> bool` that reads `DiveSimulation`'s public interface only; build one with `Scenario.when()` (a state) or `Scenario.on_event()` (an event, optionally matching), or the helpers beside them. `Scenario.start()` makes its dive; `set_scenario()` puts a Scenario on any simulation, which is how tests try the First dive's Checklist on a short layout (its conditions read Media by name, never depth). A new Scenario is a static constructor beside `first_dive()`; one that needs a start state the commands cannot reach adds a command for it on `DiveSimulation` that `prepare` calls, never a debug command. Progress is `Checklist` (`sim/checklist.gd`), owned by `DiveSimulation` and tended after every step (`_tend_checklist()`, from `advance()`, and while surfaced, so messages still arrive) with the events raised since it last looked (`_events_checked`, reset by `take_events()`). It breaks the subsystem rule on one point: it is handed the simulation on each `tend()` so the conditions can read it; it holds no reference between calls. The rules it keeps: goals are achieved once and stay so; steps tick in order, only the next step of the running phase can tick, and an event counts toward one step (the steps after one that ticks see only state that tend); a phase begins once the one before is finished, or early when its `begins_when` holds, and steps left undone before it are `MISSED`; a message is sent once its condition holds and arrives after its length at `link_capacity()` (fast up the open tunnel, a trickle through sealed rock), one at a time, oldest first. A new dive starts the Checklist afresh (`_scenario` is kept between dives). Step texts name no keys: a step's `action` names the key-map action that does it, and the panel writes `KeyMap.label(action)`. Events a Scenario's conditions need that the simulation did not raise are added to it as ordinary events (`&"course_plotted"`, `&"pulse_sent"`, `&"orders_read"`).

**The Shift dial** lives on the simulation (`set_shift_dial()`, `shift_dial()`), so the Checklist can see it readied; the view mirrors its dial into it on every turn and Shifts at it. It is a selector, not a setting: turning it leaves the Reactor's autopilot engaged.

**New minerals.** Add the mineral to `ColumnLook.MINERAL_COLOURS` (its look in the Bore) and to `SurveyStretch._MINERAL_WORTH` (its worth; defaults to 1).

## Subsystems

Heat, the plasma and stranding each live in their own plain class in `sim/`, owned by `DiveSimulation` (`_heat`, `_plasma`, `_stranding`). They are not seams: tests never build or read them, only `DiveSimulation`'s interface. The rules:

- `DiveSimulation` keeps every command, query and event; a subsystem's state reaches the outside only through a `DiveSimulation` query that delegates to it. A new query is added to both.
- A subsystem knows nothing of the layout, the path, the Stations or the survey, and holds no reference back to the simulation (a new dive swaps it for a fresh one). Whatever it needs (depth, the wobble's frequency, the surroundings' temperature, whether the Reactor's autopilot may Shift) is passed in on each call. Its tuned constants are its own `const _NAME`.
- Events a subsystem raises are appended to the `events` array the simulation passes it (`Plasma.tend()`), so `take_events()`'s catalogue still lists them all.

**Heat** (`sim/heat.gd`, `Heat`): heat made, the split into the Column and outward, hull temperature, hull wear (creep), the heat warning, how much of the Column's record survives the heat. `Heat.step()` runs once a step from `_step()` after the power is shared, with the depth. Creep is the one wear rule: none at or below the rated temperature (`hull_damage_temperature()`), above it the overheat times a stress that grows with depth; `hull_integrity()` is `1 - vessel_wear()`, `hull_creep_rate()` the wear per second, `hull_taking_damage()` whether it is wearing now (false once the dive has stopped: dead or surfaced, since the last creep rate would otherwise freeze; true while stranded, when heat soaking in creeps it), and `hull_stress()` the depth stress (1 at the surface) that multiplies creep. The hull settles toward the surrounding rock's temperature plus what it sheds, so hot rock heats it at any power. `Heat.failed()` (wear at 1) is read by `Stranding.check()`. With the Head dark, `Heat.soak()` replaces `step()`: the hull settles toward `soak_temperature()` (the surroundings plus the heat of the melt round the vessel), less what the pumps carry into the Column at the cooling share, and creeps by the same rule. `time_to_fail()` is the stranding clock worked out from that same model: the wear by any time is exact (`_soaked_wear()`: the hull's exponential settling with the creep rule summed over it, cooled while the store lasts, then not), and the time that wear reaches failure is found by bisection up to `_LONGEST_CLOCK_S` (a search limit, not tuned; longer reads as INF), so the clock and the death it predicts agree; change the soak or creep rule and the clock follows. New heat and hull behaviour goes here. The Thermal Station's setting (`_heat_split`) and its autopilot's rule stay on `DiveSimulation`, which hands the split in; while stranded the split is how hard the pumps run on the store (set to 0 at the stranding, since the pumps stop with the Head; Thermal's autopilot does not raise it).

**The plasma and the Shift** (`sim/plasma.gd`, `Plasma`): stability, tuning, the Shift's window and grade, the autopilot Shift, the heat spike and lurch of a poor Shift, Head wear, losing the plasma. `Plasma.tend()` runs once a step at the start of `_step()`, before the power is shared; `open_window()` is called on crossing a Boundary. New plasma, Shift and Head behaviour goes here. A relight (`relight(target, roll)`) strikes a lost plasma at `relight_chance()`, which falls with Head wear; the roll comes from `DiveSimulation._relight_random` (kept between dives) and the pulse is paid from the store first. A relit Head keeps its wear. Head wear reaches the Shift in one place, `_narrowing()` (1 fresh, smaller when worn), which scales the window (`window_length()`, read as `shift_window_length()`), the grading tolerance and the lateness falloff; whether the plasma still holds (`due()`) does not narrow. A worn Head's lower power is its unsteadiness term in `stability()`. A poor Shift loses the plasma two ways, both in `_make_shift()`: a disruption (its roughness times the wear already on the Head reaches `_DISRUPTION`), which leaves the Head with only that Shift's own wear, or wearing the Head through (its wear takes the Head to 1). A clean Shift adds no wear, so it can do neither, whatever the wear: that is why a relit Head worn through holds through clean Shifts. So a plasma lost by a Shift can leave any wear from about half up, and the relight rolls at that real wear. `Plasma.frequency_in(medium)` is the wobble's frequency.

**Stranding, rescue and death** (`sim/stranding.gd`, `Stranding`): what losing the plasma or the hull comes to (`check()` once a step, stranded steps included: `DIED` when the hull fails, whatever the plasma, so the stranding clock running out is the same death as any other hull failure; `STRANDED` sealed in; `BROUGHT_HOME` with the tunnel open), whether the Lithocraft is stranded or its crew dead, the repair bills (hull and Head), the rescue (its time from the open and sealed lengths, `call_rescue()` at the stranding, `wait_for_rescue()` each stranded step, its cost), the rebuy. `DiveSimulation._check_stranded()` carries the outcome out on the survey, the link and the vessel's place (`_die()`, `_strand()`, `_bring_home()`, and `_rescue()` when the rescue arrives), since those are the simulation's. It holds the emergency store (see Extension points). The tunnel's sealed length is counted on `DiveSimulation` (`_sealed_metres`, added to in `_update_tunnel()` as the Tail leaves dense rock; O(1) a step) and handed in. A stranding keeps the survey aboard (the link can still send it, on the store); the rescue brings it home and sells it, death loses it (`_lose_unsold()`). `stranding_clock()` and `rescue_time()` are live estimates at any time: stranded, running live; under way, what they would be if the plasma went now. New stranding behaviour goes here; the simulation applies what it decides. The reset itself (`new_dive()`, `_start_fresh()`) stays on `DiveSimulation`, because it resets every part of it.

## The view

- `habitat.gd` owns the `DiveSimulation`, sets each Station's attendance from `_at(station)`, calls `advance(delta)` in `_physics_process`, then takes events. Child views get the sim handed to them (`DiveView.attach(sim)`, or a public `sim` var on a `Control`).
- `_at(station)`: the crew member is seated there by the Arm, or within `STATION_REACH` of its pivot. Every Station key is gated by `_at` of its Station, once, in the key map's dispatch (see Key map); a `_key_` handler need not check it.
- Nothing is drawn over the crew's view (story 52). What the crew must know goes on a Station screen, into the Bore, or into shake and sound. The only screen-space text is the centre notice (`_show_notice(lines, seconds)`, 0 = until replaced), the F1 controls (`ControlsPanel`, hidden by default), the Tab checklist (`ChecklistPanel`, upper right, hidden by default; reads the simulation, and opening it sends `read_orders()`), the F3 `DiveView` debug overlay (hidden by default; reads only, sends no commands) and the numpad debug menu (`DebugPanel`, `view/debug_panel.gd`, hidden by default, drawn over the notice; it reads the simulation, and its keys, dispatched by the Habitat, send debug commands). The debug menu and F1 share the lower left: opening one closes the other. Keep Medium names off anything always on screen: the Medium is recognised by its look in the Bore.
- Station screens are `GimballedStation`: `show_keys(KeyMap.bindings_at(station))` puts the Station's key panel beside its screen (on the crew's right), `show_reading(text)` for text, `show_display(texture)` for a `SubViewport` texture (the Bore, Reactor and Navigation screens do this), `set_supplied(share)` dims a starved screen, `set_call(urgency)` beats the Station's tone and flashes its light. Set `call_tone_hz` / `call_pips` before `_ready`.
- Anything drawn along the Column pins each piece to its path position (`distance() - behind_head`) so it scrolls at exactly `speed()`. Never integrate speed in the view. The Bore's Column uses its own tube mesh with explicit UVs, because `CylinderMesh` shares its texture with its caps.
- Controls that sit over the Habitat set `mouse_filter = 2` so clicks reach the mouse capture. An `HSlider` sets `focus_mode = 0` so arrow keys reach `_unhandled_input`.
- `head_wear()` (the Head, from poor Shifts) and `vessel_wear()` (the hull, from heat) are different things. The Thermal screen shows the hull as `hull_integrity()` and `hull_creep_rate()`, and once sealed in `stranding_clock()` beside `rescue_time()` ("if stranded" estimates under way, the race itself while stranded).
- Hull damage is felt, never drawn (`view/hull_feel.gd`, `HullFeel`): while `hull_taking_damage()` sparks spit from the outer wall (more emitters the faster it creeps) and `shake_metres()` adds to the crew's shake; groans come from points round the ring as `AudioStreamPlayer3D`s, timed and sized by `HullGroans` from wear and `hull_stress()`, and rising with `self_destruct_hold()` while the crew holds K. The Habitat calls `HullFeel.step(delta, felt)` after `advance`. Shake from any source sums into the one `_crew.shake()` call.
- Sounds are generated until real assets exist: a looping `AudioStreamGenerator` for continuous sound (`SlipSound`), an `AudioStreamWAV` built once at `_ready` for one-shots (`HullFeel._make_groan`).

### Key map

Stand-in keys until the Stations get their own widgets, levers and knobs. `KeyMap.BINDINGS` (`view/key_map.gd`) is the one source: the Habitat's input, walking (`crew_member.gd` reads `KeyMap.held(&"walk")`), each Station's key panel, every key hint in a reading or notice and the F1 controls all read it, so none can disagree with what a key does. Never write a key's name into text by hand: use `KeyMap.label(action)` ("[N/M]") or `KeyMap.label(action, index)` ("[N]").

**Adding a key is one line** in `BINDINGS`: `{where = <ANYWHERE or DiveSimulation.STATION_...>, keys = [KEY_...], does = "what it does", action = &"name"}`, plus its handler in `habitat.gd`, `func _key_<action>(index: int)` (`index` is which of the keys was pressed; `_minus_plus(index)` reads a "-/+" pair). The panel, F1 and the dispatch follow with no other change. `key_map_test.gd` fails if the handler is missing, if two press bindings share a key at one place, or if a Station key would be shadowed where it is shown.

- **Where**: a Station binding runs only while `_at` that Station; ANYWHERE always. A key may be bound at several places (the Course keys at Navigation and the Drive); a press runs the first binding, in list order, that applies where the crew stands. List order is also the order on the panel and in F1.
- **Held keys** (`held = true`): not run on a press; read each frame with `KeyMap.held(action)` (one bool per key). Use it for walking. A key that acts on its press and while held (K, self-destruct: press to start the hold or cancel, release to stop) is a press binding whose handler starts the hold; `_physics_process` reads `KeyMap.held(action)` for the release.
- **Prompts**: `KeyPrompt.texture(code)` finds `assets/prompts/keyboard/<Name>_Key_Light.png` by Godot's key name (exceptions in `KeyPrompt._FILE_NAMES`); a key with no picture is drawn as the blank key with `KeyPrompt.glyph(code)` on it, so a new key shows even before its picture is copied in. To give it its own, copy the light image from Xelu's pack (https://thoseawesomeguys.com/prompts/, CC0) into that folder. Keys that look the same (Enter, keypad Enter) are drawn once (`KeyPrompt.distinct`).
- **A new place**: give its bindings a new `where`; F1 lists every place in `KeyMap.places()` with its title from `habitat.gd::_build_controls` (except `KeyMap.DEBUG`), and the dispatch runs them once `_wheres()` includes it.
- **The debug menu** is the place `KeyMap.DEBUG`: its keys run only while the menu shows (`_wheres()` adds it then), and numpad minus (an ANYWHERE binding, `debug_menu`) opens and closes it. Each debug binding has one key, so the menu can write its `does` beside it; `DebugPanel.LAYOUT` places each numpad key (`key`, `at`, `span`; Num Lock, which does nothing, is left out), and a key with no debug binding shows what it does anywhere, or is dimmed. Its handlers pass what `DiveSimulation.debug_*` returns to `DebugPanel.report()`, so a refusal shows on the status line (or, for the overlay, toggle the view); they are not crew controls and F1 does not list them. A new debug key: a binding with `where = DEBUG` on a free numpad key, its `_key_debug_<name>` handler, and its `debug_*` command with a test (see Extension points). The numpad's own prompts: the main keys' pictures for digits, + - and *; Xelu's "Slash" is a backslash, so `/` and `.` are blank keys with glyphs; the tall + and Enter use the pack's `_Tall_` pictures (`KeyPrompt.texture(code, true)`).

## Testing

- Test through the simulation's interface only, and assert relationships ("deeper than", "further than"), never tuned values. Build test Media from test values (`DiveTestKit.rock()`, `.basalt()`) and test layouts with `MediumLayout.uniform()` / `.layered()`.
- Use `DiveTestKit` (static): `run(sim, seconds, step)`, `run_until(sim, type, seconds, seen, step, before)` (keeps every event of the step that raised the one wanted), `types(events)`. Add shared helpers there rather than copying them into suites.
- Read expected sequences from the layout (`MediumLayout.first_dive().boundary_depths()` and `medium_at()`), never a hand-written list of depths.
- Every autopilot starts off, so a setting holds with no help. Engage the autopilot of a Station the test wants to steady itself: the Reactor's for a Shift nobody makes (`shift_test`, `stranding_test`, `repair_test`), Thermal's to keep the hull whole at full power (`steering_test`, `habitat_down_test`). Attend a Station only for a command that needs the crew there (the Drive's override, self-destruct's hold).
- The full-dive pattern is `full_trip_test.gd::_full_trip`: no autopilot engaged, the Drive set to steer gently and eased off whenever it slips, raise the time rate before each `advance(1.0)`, Shift on `plasma_frequency()` when `shift_due()`, plot pitch -90 past `TURN_AT_M`, and (by default) ease the Drive off while `heat_warning()`. Full power with all heat outward wears the hull through before the turn, so a trip that must surface either heeds the warning or cooks the Column. The careful and cooked trips are flown once per suite (`_careful_trip()`, `_cooked_trip()`); a test that goes on with the sim flies its own. Each trip takes a few seconds.
- Keep lambdas in tests on one line: a multi-line lambda as a call argument has broken GdUnit discovery.

## Gotchas

- Type inference (`:=`) from a missing class is a parse error: the run exits 105, not with a test failure.
- `runtest.*` refuses `--headless` without `--ignoreHeadlessMode`; the wrappers pass it.
